# 第一阶段接口

历史阶段接口清单。完整版本请查看 API.md。

当前只有查询接口，均无需登录。默认监听 `127.0.0.1:8080`。时间按 RFC3339 返回，UTC 使用 Z 表示。

| 方法与路径 | 说明 |
| --- | --- |
| GET /healthz | 服务存活；返回当前数据来源，不检测数据库 |
| GET /readyz | 数据来源是否可查询；数据库模式会查询 events 表 |
| GET /api/v1/events | 公开活动列表 |
| GET /api/v1/events/:id | 已发布活动详情，草稿与不存在的活动都返回 404 |

## 列表参数

| 参数 | 类型 | 规则 |
| --- | --- | --- |
| limit | 整数 | 可选，默认 20，范围 1～100 |
| before_id | 无符号整数 | 可选，正整数；只查询 ID 小于该值的活动 |

空字符串、重复提供同一分页参数、数字越界都返回 400。列表按 ID 从大到小排列；ID 是创建顺序，不是活动开始时间。

演示模式的 `GET /api/v1/events?limit=1` 返回一条活动和下面的分页信息：

```json
{
  "items": [{"id": 2, "title": "校园项目交流工作坊", "phase": "ongoing"}],
  "has_more": true,
  "next_before_id": 2
}
```

上面为节选，实际每条活动还包含 organizer_id、description、location、capacity、registered_count、remaining_capacity、registration_starts_at、registration_ends_at、starts_at、ends_at 和 created_at。具体日期由启动或初始化时间决定。

下一页带上服务器给出的 `next_before_id`。当 `has_more=false` 时，`next_before_id=null`；空列表返回 `items: []`，不会返回 null。服务多查一条记录来判断是否还有下一页。

并发新增的、更大 ID 的活动不会出现在当前继续向后翻的列表中；刷新第一页后才能看到。当前阶段没有删除和修改活动接口，分页不承诺未来可变筛选下的快照一致性。

## 活动状态

| phase | 含义 |
| --- | --- |
| not_open | 尚未到报名开始时间 |
| open | 报名开始 <= 当前时间 < 报名截止 |
| closed | 报名已截止，但活动尚未开始 |
| ongoing | 活动开始 <= 当前时间 < 活动结束 |
| ended | 当前时间 >= 活动结束 |

状态由服务时间计算，不靠定时任务更新字段。剩余名额等于 capacity - registered_count；第一阶段没有报名接口，演示数据人数为零。

## 状态码和错误

```json
{
  "error": {
    "code": "EVENT_NOT_FOUND",
    "message": "event not found"
  }
}
```

| HTTP 状态码 | 错误码 | 场景 |
| --- | --- | --- |
| 400 | INVALID_ARGUMENT | ID、limit 或游标不合法 |
| 404 | EVENT_NOT_FOUND | 活动不存在或未发布 |
| 404 | ROUTE_NOT_FOUND | 接口路径不存在 |
| 503 | SERVICE_UNAVAILABLE | 活动数据查询失败 |
| 503 | NOT_READY | 数据源或活动表不可查询 |
| 500 | INTERNAL_ERROR | 未预期的请求处理异常 |

内部数据库错误写入服务日志，不直接返回给请求者。健康检查成功只代表服务进程在处理 HTTP 请求，不能当作数据库可用的证明。
